# Pipeline Runbook

This runbook uses commands found in the repository. Build/lint commands were not executed during the
transfer scan because the request allowed creating files only in `_transfer/`.

## Pipeline Order

1. Install dependencies.
2. Recreate optional environment variables.
3. Run local dev smoke test.
4. Edit content/config.
5. Regenerate Contentlayer/tag/search artifacts through dev/build.
6. Run lint/build validation.
7. Build static export for GitHub Pages.
8. Deploy through GitHub Actions.

## 1. Install Dependencies

Purpose: reproduce the local dependency graph.

Inputs:

- `package.json`
- `yarn.lock`
- `.yarnrc.yml`
- `.yarn/releases/yarn-3.6.1.cjs`

Commands:

```bash
corepack enable
corepack prepare yarn@3.6.1 --activate
yarn install --immutable
```

Outputs:

- `node_modules/`
- `.yarn/install-state.gz`

Expected result:

- Install completes without lockfile changes.

Error handling:

- If Yarn is not 3.6.1, rerun Corepack commands.
- If immutable install fails, inspect whether `package.json` and `yarn.lock` diverged.
- Do not copy `node_modules` from the old machine.

## 2. Environment Reconfiguration

Purpose: enable optional integrations without exposing or copying secrets.

Inputs:

- `.env.example`
- `data/siteMetadata.js`
- deployment platform secret settings

Variables to recreate manually when needed:

- `NEXT_UMAMI_ID`
- `NEXT_PUBLIC_GISCUS_REPO`
- `NEXT_PUBLIC_GISCUS_REPOSITORY_ID`
- `NEXT_PUBLIC_GISCUS_CATEGORY`
- `NEXT_PUBLIC_GISCUS_CATEGORY_ID`
- Newsletter provider keys such as `BUTTONDOWN_API_KEY`, `MAILCHIMP_API_KEY`, `CONVERTKIT_API_KEY`,
  `KLAVIYO_API_KEY`, `EMAILOCTOPUS_API_KEY`, `BEEHIIV_API_KEY`

Expected result:

- Local `.env.local` exists only if integrations are needed.
- GitHub repository/environment secrets are set manually for production if required.

Manual confirmation:

- Confirm whether comments, analytics, and newsletter should be active at all.

## 3. Local Development

Purpose: preview and iterate.

Command:

```bash
yarn dev
```

Entrypoint:

- `package.json` script `dev`: `cross-env INIT_CWD=$PWD next dev --webpack`

Inputs:

- `app/`, `components/`, `layouts/`, `css/`, `data/`, `public/static/`

Outputs:

- Local server at `http://localhost:3000`
- Generated `.contentlayer/`
- Possibly regenerated `app/tag-data.json`
- Possibly regenerated `public/search.json`

Expected result:

- Root homepage renders.
- Blog pages compile.
- Contentlayer-generated imports resolve.

Error handling:

- If Contentlayer imports fail, remove stale `.contentlayer/` and restart dev.
- If `next-env.d.ts` references missing `.next/types`, run dev/build to regenerate `.next`.
- If search has no data, verify `public/search.json` was generated by Contentlayer.

Manual confirmation:

- Check `/`, `/research`, `/blog`, `/tags`, `/news`, and `/about`.
- Decide whether draft/sample content appearing in dev is expected.

## 4. Content Authoring

Purpose: add or update blog posts, authors, project cards, and static assets.

Inputs:

- Blog posts: `data/blog/**/*.mdx`
- Authors: `data/authors/**/*.mdx`
- Projects/research cards: `data/projectsData.ts`
- Static images: `public/static/images/`
- Metadata/nav: `data/siteMetadata.js`, `data/headerNavLinks.ts`

Blog frontmatter fields:

- Required: `title`, `date`
- Common: `tags`, `draft`, `summary`, `images`, `authors`, `layout`, `bibliography`,
  `canonicalUrl`

Commands:

```bash
yarn dev
```

or

```bash
yarn build
```

Outputs:

- Updated pages
- Updated `app/tag-data.json`
- Updated `public/search.json`

Expected result:

- MDX compiles.
- Post route appears at `/blog/<slug>`.
- Images referenced as `/static/images/...` load.

Error handling:

- If MDX fails, check frontmatter syntax and custom components in `components/MDXComponents.tsx`.
- If citations fail, check `data/references-data.bib`.
- If tags are wrong, regenerate `app/tag-data.json` in the intended environment.

Manual confirmation:

- Confirm whether starter posts should remain public.
- Confirm whether placeholder post/images should remain public.

## 5. Blog/Tag Rendering

Purpose: verify post lists, tag pages, pagination, and individual post layouts.

Entrypoints:

- `app/blog/page.tsx`
- `app/blog/page/[page]/page.tsx`
- `app/blog/[...slug]/page.tsx`
- `app/tags/page.tsx`
- `app/tags/[tag]/page.tsx`
- `app/tags/[tag]/page/[page]/page.tsx`
- `layouts/ListLayoutWithTags.tsx`
- `layouts/PostLayout.tsx`, `layouts/PostSimple.tsx`, `layouts/PostBanner.tsx`

Key parameters:

- `POSTS_PER_PAGE = 5`
- Default post layout: `PostLayout`

Expected result:

- `/blog` shows the first 5 non-draft posts in production.
- `/blog/page/2` works when enough posts exist.
- `/tags/<tag>` filters by slugged tag.
- Invalid page numbers return 404.

Failure modes:

- `app/tag-data.json` stale or generated in development.
- Draft post route generated but returns 404 in production.
- Tags with spaces become slugged, e.g. `next js` becomes `next-js`.

## 6. Lint and Formatting

Purpose: pre-PR source cleanup.

Command:

```bash
yarn lint
```

Entrypoints:

- `eslint.config.mjs`
- `prettier.config.js`
- `.husky/pre-commit`
- `package.json` `lint-staged`

Expected result:

- ESLint/Prettier complete.
- Files may be modified because `--fix` and Prettier write in place.

Error handling:

- If `next lint` is unsupported by the installed Next version, migrate the lint script to an ESLint CLI
  command before relying on it.
- If lint touches generated files, review the diff before committing.

Manual confirmation:

- Verify no unrelated user changes were auto-formatted unintentionally.

## 7. Production Build

Purpose: produce production output and run postbuild RSS generation.

Normal command:

```bash
yarn build
```

Entrypoint:

- `package.json` script `build`: `cross-env INIT_CWD=$PWD next build --webpack && cross-env
  NODE_OPTIONS='--experimental-json-modules' node ./scripts/postbuild.mjs`

Inputs:

- Source files
- Content
- Static assets
- Environment variables

Outputs:

- `.next/`
- `.contentlayer/`
- `public/feed.xml`
- `public/tags/*/feed.xml`
- `public/search.json`

Expected result:

- Next build completes.
- Console prints `Local search index generated...` and `RSS feed generated...` when generation runs.

Failure modes:

- Metadata still points to starter domain, producing wrong RSS/sitemap links.
- RSS assumes at least one published post.
- Missing env vars can affect comments/newsletter behavior.
- Dependency issues from Next/Contentlayer/React versions.

## 8. GitHub Pages Static Export

Purpose: match deployment behavior.

Command:

```bash
EXPORT=true UNOPTIMIZED=true yarn build
```

Entrypoints:

- `next.config.js`
- `.github/workflows/pages.yml`

Outputs:

- `out/`
- `out/feed.xml`
- `out/tags/*/feed.xml`
- Static HTML/assets for GitHub Pages

Expected result:

- `out/` is complete and can be uploaded by GitHub Actions.

Error handling:

- If images fail, confirm `UNOPTIMIZED=true` is set for static export.
- If routes are wrong, confirm `BASE_PATH` only when deploying under a subpath.
- If headers warnings appear, verify `next.config.js` does not expose `headers` when `EXPORT=true`.

Manual confirmation:

- Confirm final domain/base path before publishing.
- Confirm `data/siteMetadata.js` has the right `siteUrl`.

## 9. Deployment

Purpose: publish to GitHub Pages.

Trigger:

- Push to `main`
- Manual workflow dispatch

Workflow:

- `.github/workflows/pages.yml`

Actions:

- Checkout
- Setup Node 20
- Enable Corepack
- Prepare Yarn 3.6.1
- `yarn install --immutable`
- `EXPORT=true UNOPTIMIZED=true yarn build`
- Upload `./out`
- Deploy Pages

Expected result:

- GitHub Pages deployment succeeds and exposes a `page_url`.

Error handling:

- Check Actions logs for install/build/export failures.
- Confirm repository Pages settings.
- Confirm custom domain and DNS if used.

## Optional Steps

- `yarn analyze`: bundle analyzer build with `ANALYZE=true`.
- Replace starter README with project-specific docs.
- Remove unused starter components after build verification.
- Add a simple route smoke-test script after the first successful migration.

## Steps Requiring Manual Confirmation

- Real production URL and repository URL.
- Whether comments, analytics, and newsletter are enabled.
- Which sample/starter posts remain public.
- Whether dark mode is removed or restored.
- Whether `/about` should use Contentlayer author content or the custom profile design.
- Whether `next` should be pinned instead of `latest`.
